# سرویس همگام‌سازی پایش

این سرویس کوچک، فقط payload رمزگذاری‌شده سمت کلاینت را ذخیره می‌کند؛ محتوای فضای کاری را رمزگشایی نمی‌کند.

## پیکربندی
- .NET 8 SDK برای ساخت.
- متغیر محیطی PAYESH_SYNC_TOKENS با قالب userId=توکن تصادفی بلند؛ چند کاربر را با نقطه‌ویرگول جدا کنید. توکن هر کاربر حداقل ۲۴ نویسه تصادفی باشد.
- PAYESH_SYNC_DB مسیر پایگاه SQLite؛ برای استقرار دائمی، مسیر پایدار با مجوز دسترسی محدود انتخاب کنید.
- سرویس راه دور را پشت reverse proxy با TLS معتبر قرار دهید. پورت HTTP عمومی نکنید. شرط HTTPS در برنامه یک لایه دفاعی تکمیلی است، نه جایگزین تنظیم TLS.
- پایگاه داده و نسخه پشتیبان آن محرمانه‌اند، حتی با وجود رمزگذاری سمت کاربر؛ دسترسی و نگهداری آن‌ها را محدود کنید.

## API
- GET /health وضعیت سرویس را بدون اطلاعات کاربر می‌دهد.
- GET /v1/sync/workspace: با Bearer token و هدر X-Payesh-User نسخه و payload رمزگذاری‌شده را می‌دهد؛ برای کاربر تازه 404.
- PUT /v1/sync/workspace: بدنه JSON با expectedRevision و payload می‌گیرد. revision برای جلوگیری از بازنویسی هم‌زمان کنترل می‌شود و تعارض با 409 برمی‌گردد.
- payload باید بسته نسخه PAYESHE1 باشد؛ سرور آن را به متن آشکار تبدیل نمی‌کند.

## محدودیت مهم
این یک MVP برای آزمون است، نه سرویس آماده پرونده واقعی: نیازمند بازبینی امنیتی مستقل، TLS و میزبانی پایدار، چرخش/ابطال توکن، محدودسازی نرخ، پایش، پشتیبان‌گیری و بازیابی آزموده‌شده است. کلاینت اندروید فعلاً به این API متصل نشده است؛ بنابراین همگام‌سازی واقعی گوشی و ویندوز هنوز فعال نیست.
